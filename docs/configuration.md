# Excel 平衡配置

游戏设计者编辑 `config/` 中的三份 Excel，再在项目根目录手动执行：

```powershell
npm run config:compile
```

也可双击项目提供的一键编译入口。编译成功后重新启动开发服务，或重新构建游戏。正在进行的旧对局不会使用新配置继续重演。

## 三份工作簿

- **技能配置.xlsx**：主技能、授予子技能、公共属性、数值参数和参数含义。
- **单位配置.xlsx**：四职业、召唤物模板、属性换算和共用战斗参数。
- **经济配置.xlsx**：五级商店升级、价格、收入、库存及英雄到场回合。

召唤物的独立身体模板在单位表维护；由技能等级或施法者属性决定的生命、攻击等在对应技能行维护，避免出现两份可编辑但互相冲突的数值。

技能不是固定绑定角色的技能组。角色/职业一行维护身体属性，技能按技能 ID 和等级分别维护。

职业表的生命、魔法、攻击和护甲是已含一级三围的完整一级总值；力量、敏捷、智力成长在 T/U/V 列填写每级增加点数。第 N 回合为 N 级，仅把 `(N-1)×成长` 产生的属性增量换算并加到一级总值上。一级属性不要再加一次；永久奖励另行累计。后到场英雄同样使用当前回合等级，普通召唤物仍使用独立模板。初始四职业三围及成长按用户选择映射历史幻刺、小黑、冰女、人马，来源见单位表。

主技能有 1、2、3、6、9 点五档。4/5 点使用 3 点档，7/8 点使用 6 点档；6 和 9 点行保存该档最终有效数值，不要在同一行再手动重复叠加 Super/Gaben。升级的叠加或替换方式仍由各技能机制决定。原生授予子技能另表使用原生等级，不把原生四级当作 AA 四点。

前摇、后摇、冷却和持续时间填写毫秒；距离填写 Dota 原生单位，编译器统一换算到当前引擎。主参数每格只填一个数字，超过十个参数使用扩展参数表。按参数字典确认含义与单位，不要通过移动列来重新定义参数。

数值单元格支持数字常量。0 是有效值；缺少必需参数会报错。首版不以公式的缓存结果作为运行配置，批量计算后请粘贴为数值。技能依赖攻击力、生命、属性或层数时，表里调整系数，程序仍实时计算结果。

## 编译和校验

`npm run config:check` 检查工作簿业务内容是否与已编译配置一致。开发服务、构建和 CI 都执行这个只读检查，发现未编译修改时会给出编译提示，不会偷偷自动更新配置。

手动编译也会从原图生成大招专用 SVG 图标资产：保留原图像素，在图标内部嵌入紫金边框。该显示资源不改变平衡配置 hash；图标缺失或过期时，一致性检查同样提示执行 `npm run config:compile`。

校验错误定位到工作簿、工作表和单元格。重复 ID、缺失等级、非法类型、错误参数、无效枚举和必需数值空白都不能发布。修改列宽、颜色或其他样式不会改变业务配置 hash。

源码仓库提交 Excel、参数映射和已编译配置。浏览器读取已编译内容，不读取 Excel，也不需要本机美术来源工程。普通构建、CI 和游玩不依赖 E 盘。素材导入保留来源证据，不能覆盖设计者维护的平衡配置。

结构容量继续固定为 8 位玩家、最多 5 名英雄、每英雄 4 技能槽、4 暂存和 12 商店位置。可配置商店普通商品开放数，但最多 10 个，末两格 God 仍未启用。

## 来源与存档

优先级为用户明确自定义、AA 明确规则与数值、相容的历史 Dota 字段、明确标注的项目工作值。Wiki 是研究与补缺来源，不自动把历史 AA 技能更新为现代 Dota。

技能前摇和后摇是机械属性，不由美术帧数决定。四职业初始转身速率 18rad/s 是历史基类候选的项目换算，匀速转向不代表已还原原生加速曲线。完整来源边界见版本验证说明和机制覆盖报告。

配置 hash 覆盖技能、单位、经济和战斗规则，参与游戏及战斗恢复校验。不兼容旧存档会保留备份并提示，不能用新数值重演旧战斗。请在完成配置修改后开启新局。
