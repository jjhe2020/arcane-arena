# 离线平衡实验

在项目目录运行下列命令。首次使用需完成 `npm ci`。

```powershell
npm run balance:run -- run --pairs 100000 --workers 4 --out output/balance-r14
```

一对阵容打两场，中途交换出场方向。示例目标为 20 万场，可根据第一轮实际显示的速度调整线程或目标。目标默认 10,000 对，默认采用种子 20261105、英雄等级 15。不同种子和回合适合放到独立目录。要复跑同一组阵容，保持种子、回合和战斗快照一致即可，线程数可以变化。

## 暂停、续跑与报告

在另一个终端运行这些命令，`--out` 使用同一个目录。

```powershell
npm run balance:run -- status --out output/balance-r14
npm run balance:run -- pause  --out output/balance-r14
npm run balance:run -- resume --out output/balance-r14
npm run balance:run -- report --out output/balance-r14
```

`pause` 等在途批次写盘后暂停派发，控制台会显示实际保存的进度。`resume` 解除暂停。如果程序已退出，先解除暂停，再运行原来的 `run` 命令。按 Ctrl+C 会让正在计算的批次完成后保存退出。重新运行可使用新的 `--workers` 或更大的 `--pairs`，此前完成的场次仍计入目标。

`run.json` 保存参数和 SHA-256 校验值，隐藏的 `.engine-*` 目录保存本次战斗引擎及技能目录。两者与 `results.bin` 一起构成续跑所需的文件。每对结果占 1 字节，运行中分批追加。强制结束进程后若遗留 `run.lock`，先用 `status` 确认 `running` 为 `false`，再删除该目录里的 `run.lock` 并续跑。需要对照新版本时改用新的输出目录，以生成对应的引擎快照。

达到目标后自动生成 `report.json`。`report` 可在运行中、暂停时或全部完成后重新读取已写盘的数据并生成报告。报告的 `complete` 字段标记采样目标是否完成。`overview` 汇总各等级的高低排名及三类组合，完整数据位于同文件下方。

## 采样和装配

- 每方选五位英雄，四种模型各一位，额外模型按阵容对轮换。同一对双方使用相同的模型数量和默认站位，隔离神、附魔与商店经济的影响。
- 现有目录含 168 项普通技能、62 项终极技能。每个阵容抽 15 项普通技能和 5 项终极技能，满足每位英雄四个技能格且最多一个终极技能。普通与终极组分别分块洗牌，同组每个区块至多出现同一技能一次。每项技能的 3、6、9 级在每三个区块中独立打乱顺序，兼顾随机性与覆盖。分组规则使单项普通技能的抽中频率略高于单项终极技能。
- 每项技能的四模型优先级收录在 `src/skill-model-preferences.ts`。按 9、6、3 级依序放进仍有合法空位的最优模型。同级装配顺序由该阵容种子打乱。若英雄还没有终极技能，普通技能会预留最后一格。

## 读取结果

- `skillLevels` 提供每项技能各等级的实战胜率 `winRate`、胜平负计数，以及平局计半胜的 `winScore`。 `effect` 是胜分相对 50% 的差值。
- `sameHeroPairs` 统计两项技能同装一个英雄的情况，`sameTeamPairs` 统计同队的情况，`opposedPairs` 统计分属敌我的情况。后者以 `first` 所在队的胜分表示方向。 `effect` 是实测胜分减去单技能等级的预测胜分。预测用阵容对分成两折交叉拟合，按各技能等级的加法模型估算。两边都拥有同一组合而无法判定方向的阵容对会跳过。
- `provisional` 表示样本少于 200 对。标记为 `flagged` 的行达到 200 对、相差至少 3 个百分点，并超过多重比较筛选门槛。区间按阵容对计算，交换方向的两场合为一个观测。不同技能组合在合法配装下的样本量会不同，例如两项终极技能无法同装一名英雄。报告是调平候选筛查，可用新种子或定向配装复测具体机制。
