## 2. 技术和表现边界

- 技术栈：TypeScript + Vite + Three.js。
- 游戏运行时以二维序列帧、平面旋转和图层合成为主，非必要不增加实时三维内容。
- 战斗相机严格90°正顶视，延续现有几何卡通奇幻风格。
- 桌面与横屏移动端支持4:3至21:9的布局范围，包含16:9；比例变化不改变世界距离、战斗边界或模拟结果。
- 美术源可以使用Blender制作，但这不意味着游戏运行时加载三维角色模型。
- PokéBonk作为跨端游玩体验参考，不据其体验推断其内部技术实现，也不将其生存玩法纳入本项目。

## 4. 四职业与严格还原如何同时成立

四职业沿用现有角色库：近战刺客、远程射手、远程法师、近战肉盾。

用户确认的是职业数量与男女为皮肤，不是四职业的完整数值。生命、法力、攻击、护甲、攻速、射程、成长、品质与获得方式仍需形成四职业规则表。UI样例数据不能直接升级为正式战斗数值。

同职业的男女皮肤在相同状态下具有相同属性、碰撞、移动、攻击与施法能力；动画不同不能改变伤害时点或概率结果。职业名称本身不自动授予背刺、跳后排、嘲讽或专属技能。

由“四职业＋5英雄队伍”推导的工作默认：允许同职业重复上场，各英雄拥有独立实体ID、技能和状态；不默认强制每个职业至少一名，也不新增第五职业。该条是必要实现推导，不冒充用户逐字确认。

还原优先级为：用户明确自定义规则 > 已核实的AA具体版本规则与覆盖修改 > 与其相符的Dota底层行为。不得直接用当前Dota版本覆盖历史AA差异。

5B提高的是剩余战斗机制的还原目标，不撤销1A、3C、7A的自定义。项目可声明“具有明确自定义的AA核心玩法”，不能宣称整个产品与某版AA逐项完全相同。

关闭“独立装备系统”不等于删除技能升级所授予的物品型被动效果。若Super/Gaben本身包含攻击特效、光环等效果，它仍属于该技能还原范围，应作为内部机制实现，不额外引入试炼、装备选择和装备槽。

## 5. 技能目录与美术接入

- 当前核对起点为230项AA定义。目录外6项美术保留为资源，不自动增设正式商品或自创升级规则。
- 全量覆盖目标包括适用的基础等级、Super、Gaben和附带效果；不能用重复动画档数充当独立技能数量。
- 230项覆盖目标不等于每局同时开放230项；用户后续确认每局随机100项。没有宣称230项来自同一AA补丁。
- 当前快照的189项可见、41项未显示仍保留来源记录；用户后续选择以230项作为抽取100项的候选目录，因此不再将可见性直接当作本项目商店资格。
- 现有236项美术已获认可，原基础效果中的12项AA升级档仍有扩展缺口。视觉认可不代表机制、碰撞或引擎表现已验证。
- 通过稳定技能ID、素材ID、准确版本及SHA连接美术；按用户2026-10-29授权采用同项最新版本，关联运行清单中的继承动作，避免把最新追加动作包误当成包含全部旧动作的独立完整包。
- 高清母版只作为来源。游戏使用独立生成的运行图集、尺寸档与加载清单，按需加载和释放。

## 6. 对局、AI与时间

已确认：单局8方，7个AI持续构筑；难度通过AI金币倍率控制，初始提供1.0、1.5、2.0倍。

以下为本轮采用的工程工作默认，不作为原作已取证事实：

- 金币倍率乘同回合按规则发放的基础预算，不乘玩家当前余额或实际消费；退款不重复乘倍率，商品价格不随倍率变化。
- AI按职业、技能类别与已有组合做简单评分，选择购买、刷新、商店升级和技能分配。先改善有效构筑，再尽量用完预算；不为清零金币循环买卖。
- 玩家与AI的单位共用同一战斗模拟。AI之间的比赛也据此结算，不随机编造排名或胜负。
- 共享池、返池与禁选遵循后续冻结规则。若采用共享池，采购调度必须明确，避免AI瞬间独占库存，或玩家仅靠拖延现实时间改变AI花钱量。
- 本轮战斗状态与下轮计划分离；当前战斗中取下、出售或升级技能，不改变当前战斗中的对应技能效果。
- 无时限备战及暂停不能重复发钱、刷新商店或触发下一阶段。加速只改变观看所用现实时间，不改变相同输入下的模拟结果。
- 关卡模式、联网对战、God、独立装备、试炼、Wonder及RA分支升级不属于首版范围。

## 7. 移动端、存档与性能默认

- 触控提供点击选择＋明确操作路径，拖拽为便捷方式；必要操作不能只依赖鼠标悬停或右键。
- 保留12商品/20技能槽/4暂存的容量，手机通过面板切换访问；不能通过缩小到不可读或删除功能完成适配。
- 手机竖屏显示旋转提示；进入后台或切至无法操作的状态时，暂停与恢复采用可复现的单机策略，详细状态转换在实现前列入规则表。
- 暂以中端手机稳定30FPS、桌面60FPS作为性能工作目标；具体设备、浏览器、分辨率与满载场景待实测确定，不能称所有手机已经受支持。
- 默认本浏览器自动存档，保存足以恢复的对局状态、随机状态与规则版本，避免刷新重抽。没有承诺跨设备同步或首次加载后完全离线。
- 音效、音乐与缺失UI素材列入资产缺口，不阻塞规则考证和战斗机制验证。

1. 建立完整目录映射、规则来源和差异表；研究四职业数据与严格还原需要的底层机制。

3. 完成一整局8方对战、简单构筑AI、经济、淘汰、保存恢复及横屏交互。
4. 按完整目录扩展和逐项校准，补足美术接入、性能与兼容性验证。

上述步骤是实施顺序，不是将首版缩减到小技能池。全部目标目录及适用等级、关键联动、完整比赛流程和目标设备验收完成后，才能称首版完成。

当前已开始实现游戏；本文件本身不证明全部机制、全量交互或设备性能已经达到最终要求。
