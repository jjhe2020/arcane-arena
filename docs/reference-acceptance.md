# 230 技能原作逐项验收

目标仍为全部230主技能的机制、时序、Super、Gaben及相关组合逐项验收，包含其授予能力的实际效果。保留AA数值、四职业和已确认自定义；非数值细节优先研究Dota Wiki，已知版本冲突对照历史变更和固定Valve数据。环境范围继续按已确认平面竞技场处理。

当前进度表由程序生成：[逐项状态](skill-reference-status.md)。单组原始记录位于 `references/dota-wiki/acceptance/`，完整机器报告为 `public/data/reference-acceptance.json`。未开始的技能也保留在230项总表中。

## 每项验收证据

- 保留AA原始英文基础、Super、Gaben条款，并说明中文误译或歧义。关键词追溯同英雄技能、天赋、神杖、魔晶、命石或物品，不把相似名称当作唯一对应证据。
- 每条机制要求绑定实际读取的Wiki/历史来源、访问日期、版本范围及具体结论；兼容推导与直接资料结论分开。没有充分资料的规则不因测试通过而变成原作事实。
- 测试断言实际结果，包括时点、目标资格、伤害类型、攻击/法术分类、状态、资源、归属、释放或中断及适用组合。全目录可运行测试不代替保真验收。
- 一条测试可证明多个明确条款；同一个条款不能借另一项技能的笼统“已实现”标记通过。
- 整项放行需要明确完成所有描述条款审查，五个维度都有完整记录，未解决项清空，并具备当前代码的真实通过结果。不能用少数样例或分支注册率提高整项通过数。

## 命令和证据有效期

`npm run reference:verify`执行所有`tests/reference-*.test.ts`，核对测试前后代码/配置指纹，保存`artifacts/reference-acceptance-proof.json`并更新230项报告。脚本将具名Vitest结果与每条要求逐项匹配。缺少测试、来源绑定或当前指纹时，不计为已验证。

`npm run reference:report`只重新整理已有证据，不执行测试。构建时也会更新报告；代码或配置变化后，过期证据显示为过期，不自动沿用绿灯。GitHub发布工作流在构建前重新运行专用验收。

主报告的`fullyReferenceVerified`才是整技能放行计数，`resultTestPassed`只是已证明的具体实现结果。`reviewStarted`也不代表完成。

## 当前需要继续追踪的引擎问题

- 地面目标冻结已加入显式接口并首先用于酸性喷雾。其它点目标能力需要逐项审查后接入，不能因为通用框架存在就宣称全部技能已迁移。
- 攻击吸血与法术吸血需要分开核验历史口径；7.20攻击吸血的过量伤害规则不能套到法术吸血。幻象、召唤物、友方伤害与物品来源还需逐族校准。
- 幽灵船偿还和虚妄之诺最终结算已取消再次法术吸血；原始伤害归属账本继续保留。历史虚妄之诺与护盾、回光返照的优先级，以及其它延迟形式的初次吸血基数仍需查清。
- 上古封印跨施法者的原生修饰器规则还没有直接证据，不能仅以同名状态或`MULTIPLE`标记的通用解释确认。
- 攻击动作替换、技能发起的攻击、原生攻击修饰以及统计ID各自独立，仍需逐族检查；当前已新增同击替换、保证暴击候选、命中前减甲、攻击点事件及动态攻击时钟的结果测试。

这些问题属于持续目标的待办，不以“阶段可玩”替代全部技能原作验收。
