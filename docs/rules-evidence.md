## 2. 规则状态与证据字段

每条规则区分：用户明确自定义、已证实参考规则、待核实、项目工作假设。每个技能/机制至少记录稳定ID、适用版本、来源位置、原文或数据字段、项目解释、差异原因和验证方法。

对英文/中文冲突、技能标签与描述冲突、Super/Gaben是否累积、引用当前Dota行为等情况单独记录。不能把美术演示中的工作假设改写为“原作就是如此”。

严格还原的裁决顺序：已确认自定义优先；其他规则优先同版本可验证实现或实测，其次官方数据/说明与补丁；无法确认的行为保留待核实，原型假设必须显式标注。未找到官方完整实现不等于不存在，也不等于已得到可以一比一移植的源代码。

## 4. 首批技术验证应覆盖的失败场景

- 5英雄中存在重复职业，独立技能和状态不串到同职业另一实体；替换男女皮肤不改变模拟结果。
- 玩家战斗中出售或升级技能，当前战斗伤害及效果不变，下一轮正确生效。
- AI金币增加后不会因为无意义买卖/重配而破坏已有构筑；随机对局不要求逐场必然更强，但应记录策略质量与预算使用。
- 非玩家之间的战斗通过同一模拟计算；查看其他棋盘不影响其胜负。
- 暂停、加速、手机后台与刷新恢复不重复消费/发钱，不重新抽取随机结果。
- 召唤密集、持续范围伤害、连锁触发及复活场景能正确结算并回收资源。
- 手机横屏实际CSS尺寸下完成购买、暂存、装备、排序、查看详情和准备；4:3/21:9不改世界坐标。
- 高清母版不整包常驻手机显存；加载失败、资源释放与重新进入对局可恢复。
